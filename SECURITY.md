# Security policy

Version 1.1 provides private local accounts and encrypted locked workspaces by Jason Stys, not a hosted/shared-team service or security certification. Report vulnerabilities privately through GitHub's private vulnerability reporting when enabled, or contact Jason via the LinkedIn link in README. Never post credentials, real documents or account roots in public issues. Do not deploy the separate legacy demo with real records.

Defense boundaries: server roles/workspace/customer ACLs; opaque expiring hashed sessions; scrypt password storage; CSRF and same-origin writes; sanitized HTML and scriptless previews; attachment-only raw sources; upload/archive/text/table/page/image limits and timed subprocesses; transactional mapped data and hash-based sales idempotency; no private PWA caching; model opt-in with scoped context and checked citations.

Private mode adds owner-separated archives/settings, independent vault proof for every session, AES-256-GCM locked storage, durable request/auth throttles, human-idle sealing, once-use login recovery and current-password-confirmed own-account deletion. It validates exact Host/Origin before body parsing, has no global provider-key/factory fallback, and requires reviewed destination revision consent for deliberate external AI. Native renderers are sandboxed with no Node/preload, no permissions, external requests/navigation or popups. Scripts/assets are same-origin; sanitized documents have scriptless sandbox frames. These are preventive controls, not an antivirus/ad-blocker guarantee against extensions, malware or supply-chain compromise.

Non-guarantees: no complete parser exploit sandbox, antivirus/CDR, universal OCR/vision, certified compliance, prompt-injection proof, SSO, public/shared-team hosting or zero-knowledge against the local service. Windows parser memory is not hard-limited by this code. Public adversarial uploads need hardened worker resource/egress policies. Active documents/keys are plaintext on the trusted OS; crash recovery can retain plaintext until sealed. Forgotten vault phrases are irrecoverable; no backdoor. Plaintext exports and old demo data require separate protection. Own deletion does not erase OS backups/exported files, securely overwrite SSDs or affect copies deliberately sent to a model provider. Native packages are unsigned/not notarized. A legacy custom AI factory is trusted developer code; installed private mode cannot load arbitrary modules/models from uploads.

Dependency scans and CodeQL are evidence checks, not proof of absence of vulnerabilities. See [private accounts](docs/private-accounts.md), [support limits](docs/formats.md), [release checklist](docs/release-checklist.md) and [current validation](docs/validation-v1.1.md).
